데이터베이스 객체
- 데이터베이스 내에서 데이터를 저장하고, 관리하고, 빠르게 조회하기 위해 정희하는 논리적 구조이다.
- 종류
    - 테이블 : 데이터를 row와 column 형태로 저장하는 가장 기본적인 저장 공간
    - 인덱스 : 책의   색인처럼, 테이블에서 데이터를 빠르게 검색할 수 있도록 성능을 높여주는 객체이다.
    - 뷰 :하나 이상의 테이블에서 파생된 가상 테이블이다. 복잡한 쿼리를 미리 저장해 두거나 보안 목적으로 사용한다.
    - 시퀀스 : 중복되지 않는 고유한 숫자를 자동으로 생성해주는 객체이다. (주로 기본키 생성할 때 사용)
    - 저장 프로시저 : sql 문장의 묶음으로, 특정 로직을 데이터베이스 내에 저장해 두고 함수처럼 호출해서 사용한다.
- 데이터베이스 내에서 객체를 작성할 때는 종류가 달라도 이름이 겹치면 안된다.

스키마
- 데이터베이스 객체는 스키마라는 그릇 안에서 만들어진다.
- DBMS에서 스키마를 "데이터베이스 객체들을 담는 컨테이너(폴더)" 개념으로 사용한다.
    - 설계 관점에서는 설계도와 같은 개념이다.
- 각각의 다른 스키마에서는 이름이 중복되어도 상관없다.

테이블 생성(CREATE TABLE)
- default 값을 설정하지 않은 상태에서 not null 제약조건을 건 컬럼에 값을 입력하지 않으면 에러가 발생한다.

테이블 삭제(DROP TABLE)
- 테이블 자체와 그 안에 들어있던 모든 데이터를 통째로 영구 삭제한다.
- 실행할 때 확인을 요구하지 않기 때문에, 실무 운영환경에서는 조심해서 사용해야 한다.
- 데이터만 비우고 싶을 때는 "TRUNCATE TABLE 테이블명"을 사용한다. (더 빠름, 틀은 남겨둠)

테이블 변경(ALTER TABLE)
- 열 구성을 변경할 때, 사용한다.
- ADD 하부명령을 사용할 경우, 기존 데이터행이 존재하면 추가한 열의 값이, 기본값으로 데이터가 저장된다.
- MODIFY를 사용하여 자료형, 기본값, 제약 등의 속성을 변경 가능
