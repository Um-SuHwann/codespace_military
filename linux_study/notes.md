[1일차]
1. ls의 아이노드(Inode)
- Inode : 리눅스 파일 시스템은 파일의 이름과 파일의 진짜 데이터를 따로 분리해서 관리함.
- 실제 운영체제는 아이노드 번호라는 고유의 실별자를 통해서 파일의 크기, 소유자, 권한, 데이터가 저장된 위치를 추적한다.
- ls -i
2. 터미널 프로세스
- 운영체제에서 공부했던 시스템 콜이 셸 프로그램 내부에서 발생.
    - ls를 입력하면, 셸 프로세스가 fork()로 자신의 자식 프로세스 생성, 자식 프로세스는 exec()를 통해서 ls프로그램 반환되어 실행
3. 디렉토리 구조의 철학 : 모든것은 파일이다.
- 리눅스의 철학 : 컴퓨터 안의 모든 자원을 파일 형태로 다룬다.

[2일차]
1. 파일권한(chmod) UGO모델과 권한 비트
- 세 가지 주체(UGO) : 리눅스는 파일의 권한을 User, Group, Others의 3가지 주체로 나누어 관리한다.
- rwx의 이진수 해석 : 읽기(r=4), 쓰기(w=2), 실행(x=1)을 더해서 숫자를 만든다.
- 운영체제 관점 : 프로세스가 시스템콜을 통해 파일을 열려고 할 때, 커널은 현재 프로세스를 실행중인 사용자의 UID와 파일의 소유권 정보를 대조하여 접근권한을 허용할지 거부할지를 커널레벨에서 즉시 차단.
2. cp와 mv의 커널 내부 차이
- cp : 디스크의 실제 데이터 블록을 새로 읽어서 완전히 새로운 물리적 공간에 똑같이 카피하고, 새로운 Inode를 할당한다. 디스크 용량이 그만큼 추가로 소모된다.
- mv : 디렉토리 파일 내부에서 아이노드 번호를 가진 파일의 디렉토리 엔트리만 바꿔주는 작업. 엄청나게 빠름.

[3일차]
1. 배운 명령어 리스트
- echo -e : -e를 사용하면 Esape Sequence 를 사용할 수 있다. 안쓰면 백슬래시도 그대로 출력함.
- grep : 파일 전체 내용 중 원하는 단어가 들어간 줄만 찾을 수 있다.
- |(pipe) : 앞 명령어의 출력 결과를 끊지 않고 바로 다음 명령어의 입력으로 꽂아주는 운영체제 수준의 데이터 통로이다.
2. 표준 입출력과 파일 디스크립터(FD)의 리다이렉션(>)
- 컴퓨터가 켜질 때 기본적으로 프로세스에는 3개의 파일 디스크립터가 열린다.
    - 0(표준 입력, 키보드)
    - 1(표준 출력, 모니터)
    - 2(표준 에러, 모니터)
- ">"기호를 쓰면, 커널은 출력을 1로 보내는 대신 지정된 파일을 열어 그곳으로 데이터 스트림을 향하게 한다.
3. 파이프(|)의 커널 내부 버퍼와 동기화
ps -ef | grep bash에서, ps와 grep은 다른 프로세스로 동시에 독립적으로 돌아감.
- 파이프 : 운영체제가 pipe() 시스템 콜을 호출하면, 메모리 커널 영역에 Ring Buffer라는 임시 저장소를 만든다.
    - 하나의 파이프를 조작하기 위해서 운영체제는 2개의 FD를 부여한다.
        - pipefd[1] (쓰기종단) : 파이프의 입구이며, write()시스템 콜로 데이터를 밀어 넣을 수 있다.
        - pipefd[0] (읽기종단) : 파이프의 출구이며, read()시스템 콜로 데이터를 꺼내올 수 있다.
- ps의 출력은 쓰기종단에 들어가고, grep는 읽기종단에서 데이터를 가져온다.
    - 만약 ps 프로세스가 grep 프로세스보다 빨라서 버퍼가 가득차면, ps 프로세스는 blocking 상태가 되고, 반대로 버퍼가 비어 있다면 grep 프로세스가 데이터가 들어올 때까지 blocking 상태가 된다.
    -> 운영체제 커널이 버퍼와 블로킹 매커니즘으로 프로세스간의 속도 차이를 조율해준다.
